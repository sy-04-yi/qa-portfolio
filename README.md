# 若依管理系统（RuoYi-Vue）软件测试作品集

本仓库记录了一个完整的软件测试实习准备项目：基于 RuoYi-Vue 后台管理系统，完成测试用例设计、接口测试、数据库交叉验证与缺陷管理全流程。

## 项目概况

| 项目 | 说明 |
|---|---|
| 被测系统 | RuoYi-Vue 前后端分离后台管理系统 |
| 技术栈 | Spring Boot + Vue + MySQL + Redis |
| 测试类型 | 功能测试、接口测试、数据库验证、安全测试 |
| 使用工具 | Postman、DBeaver、禅道、Xmind、Excel |

## 交付成果

### 1. 测试用例（110 条）
- 文件：`test-cases-110.xlsx`
- 覆盖模块：登录、用户管理、角色管理、菜单管理、部门管理、字典管理、参数设置、公告管理、岗位管理
- 设计方法：等价类划分、边界值分析、场景法、权限异常、特殊字符
- 每条用例包含：用例编号、模块、标题、前置条件、操作步骤、预期结果、用例类型、备注

### 2. 测试脑图（三层结构）
- 文件：`test-mindmap.xmind`
- 中心主题：若依管理系统，10 个功能模块、50 个功能点

### 3. 接口测试（30 条，全部执行通过）
- 文件：`api-collection-30.json`（Postman 集合，token 已内置，可直接导入执行）
- 覆盖：GET 12 条、POST 3 条、PUT 3 条、DELETE 1 条、鉴权与异常场景 11 条
- 每条断言校验 HTTP 状态码与业务 code
- 异常场景：无 token、假 token、参数非法、类型不匹配、方法不支持
- 详细报告：`api-test-report.md`

### 4. SQL 交叉验证
- 文件：`sql-practice-1121.sql`、`sql-crosscheck-1122.sql`
- 5 类查询：SELECT / WHERE / GROUP BY / JOIN / 交叉验证
- 5 组界面-数据库交叉验证：新增、修改、删除、搜索、分页
- 验证点：接口修改的昵称在数据库中查到，证明数据落库正确

### 5. 缺陷管理（禅道提交 13 个）
- 文件：`bug-list.md`
- 13 个有实测证据的缺陷，含标题、复现步骤、严重级别、优先级
- 另有 5 个验证点确认系统防护到位（未提单，作为正面验证结果）
- 代表性缺陷：
  - 验证码刷新后旧验证码未失效（安全问题，严重）
  - token 不带 Bearer 前缀仍能鉴权（安全问题，严重）
  - 前后端密码规则不一致（6-20 位 vs 5-20 位）
- 缺陷分布图：`screenshots/chart_severity.png`、`screenshots/chart_module.png`

### 6. 完整测试报告
- 文件：`test-report.md`（在线预览）、`test-report.docx`（Word 版）
- 六章结构：概述、测试环境、执行情况、缺陷统计与分析、遗留风险、结论与上线建议
- 结论：有条件通过（核心功能可用，2 个安全类严重缺陷需修复后回归）

### 7. 简历初稿
- 文件：`resume-draft.md`
- 按测试实习岗位模板撰写，项目数字与本仓库交付物一致

## 测试过程要点

- **鉴权机制**：理解 token 作为通行证的鉴权原理，JWT Bearer  Token 的使用与 401 排查
- **接口测试**：掌握 GET/POST/PUT/DELETE 四类方法、JSON 请求体、断言编写
- **交叉验证**：界面操作后查库比对，验证数据真正落库
- **逻辑删除**：理解 `del_flag` 标记删除机制（0 正常 / 2 已删除）
- **缺陷判断**：区分"真缺陷"与"系统防护到位"，设计 18 个验证点，13 个确认为缺陷
